# מערכת ניהול תורים - משרד ייעוץ פיננסי והשקעות

מערכת לניהול תורים (Appointments), לקוחות, חשבוניות מס ולידים עבור משרד ייעוץ פיננסי המתמחה בהשקעות בשוק ההון ובנדל"ן.
המערכת נכתבה בשפת Python, משתמשת בבסיס נתונים SQLite לשמירת המידע באופן מתמשך (persistent), וניתנת להפעלה בשתי צורות: **ממשק ווב גרפי** (Flask) ו**ממשק שורת פקודה** (CLI).

## תכונות עיקריות

- **ניהול תורים** - הוספה, עדכון סטטוס (ממתין / בוצע / בוטל), מחיקה ושחזור
- **ניהול לקוחות** - הוספה, צפייה, מחיקה ושחזור, כולל דף פרטי לקוח עם היסטוריית תורים וחשבוניות
- **ניהול חשבוניות מס** - יצירת חשבונית עם מספר ייחודי, סכום ותאריך, מחיקה ושחזור
- **ניהול לידים** - הוספה, עדכון סטטוס, המרה ללקוח, מחיקה ושחזור
- **מחיקה רכה בכל הישויות** - שום נתון לא נמחק לצמיתות; ניתן לשחזר כל רשומה שנמחקה, ולצפות ברשומות פעילות / מחוקות / הכל
- **ממשק ווב** נוח ורספונסיבי (Flask + Bootstrap 5, תמיכה מלאה בעברית מימין-לשמאל) לצד ממשק שורת הפקודה המקורי
- **נתוני דוגמה** נטענים אוטומטית כשמסד הנתונים ריק, כדי שהמערכת לא תיראה ריקה בהרצה ראשונה
- **פתיחה אוטומטית של הדפדפן** בעת הרצת שרת הווב

## דרישות מערכת

- Python 3.x
- Flask (להרצת ממשק הווב בלבד - ממשק שורת הפקודה עובד גם בלי Flask, עם המודול המובנה `sqlite3`)

## הרצת הפרויקט

### אפשרות א' - ממשק ווב (מומלץ)

```bash
python app.py
```

השרת עולה על `http://127.0.0.1:5000`, והדפדפן נפתח אליו אוטומטית כעבור כשנייה. ניתן גם לגשת מכל מכשיר אחר באותה רשת דרך כתובת ה-IP המקומית של המחשב (מוצגת בקונסול בעת ההרצה), מכיוון שהשרת מאזין על `0.0.0.0`.

הגדרות אופציונליות באמצעות משתני סביבה:

| משתנה סביבה | ברירת מחדל | תיאור |
|---|---|---|
| `PORT` | `5000` | הפורט עליו יאזין השרת |
| `FLASK_DEBUG` | `0` | קבעו ל-`1` כדי להפעיל מצב Debug (Auto-reload + Debugger) |
| `SECRET_KEY` | ערך פיתוח קבוע | מפתח החתימה של Flask להודעות Flash - **חובה לשנות בפריסה אמיתית** |

### אפשרות ב' - ממשק שורת פקודה (CLI)

```bash
python main.py
```

תפריט אינטראקטיבי בעברית לניהול כל הישויות במערכת ישירות מהטרמינל.

> **הערה:** תצוגת טקסט בעברית במסוף Windows עשויה להיראות הפוכה. ניתן לתקן זאת בהרצת הפקודה `chcp 65001` לפני הרצת התוכנית.

בשתי הצורות, בהרצה הראשונה קובץ בסיס הנתונים `appointments.db` נוצר אוטומטית מתוך `schema.sql`, ואם הוא ריק - מתמלא בנתוני דוגמה (ראו [נתוני דוגמה אוטומטיים](#נתוני-דוגמה-אוטומטיים)).

| `appointments_manager.py` | פונקציות CRUD + מחיקה רכה לניהול תורים |
| `customers_manager.py` | פונקציות CRUD + מחיקה רכה לניהול לקוחות וחשבוניות מס (בונוס 1) |
| `leads_manager.py` | פונקציות CRUD + מחיקה רכה לניהול לידים (בונוס 2) |
| `main.py` | ממשק משתמש בשורת הפקודה - תפריט אינטראקטיבי |

| `templates/` | תבניות HTML (Jinja2) של ממשק הווב, מבוססות Bootstrap 5 RTL |
| `requirements.txt` | תלויות Python להתקנה עם pip |
| `appointments.db` | קובץ בסיס הנתונים (SQLite) - נוצר אוטומטית, לא מצורף להגשה |

## מבנה בסיס הנתונים

| טבלה | תיאור |
|---|---|
| `customers` | לקוחות (שם, טלפון, אימייל, כתובת) |
| `appointments` | תורים, מקושרת ל-`customers` באמצעות מפתח זר (Foreign Key) |
| `invoices` | חשבוניות מס, מקושרת ל-`customers`, עם מספר חשבונית ייחודי (UNIQUE) |
| `leads` | לידים (פניות פוטנציאליות) |

לכל הטבלאות הנ"ל יש עמודת `is_deleted` (`INTEGER NOT NULL DEFAULT 0`) המשמשת למחיקה רכה - ראו הרחבה בסעיף הבא.

## מחיקה רכה (Soft Delete)

**מה קורה כשמוחקים לקוח שיש לו תורים או חשבוניות?** במקום למחוק רשומות לצמיתות (מה שהיה גורם לשגיאת מפתח זר אם ללקוח יש תורים/חשבוניות), כל פעולת "מחיקה" במערכת היא **רכה**: הרשומה מסומנת כ-`is_deleted = 1` ומוסתרת מהתצוגות הרגילות, אך נשארת בבסיס הנתונים וניתנת לשחזור מלא.

- **מחיקת לקוח משדרגת (cascade) לתורים ולחשבוניות שלו** - כל התורים והחשבוניות של הלקוח מסומנים כמחוקים גם הם, כדי לשמור על עקביות. שחזור הלקוח **אינו** משחזר אוטומטית את התורים/החשבוניות שלו - יש לשחזר אותם בנפרד במידת הצורך.
- מחיקת תור, חשבונית או ליד משפיעה רק על אותה רשומה בודדת.

לכל ישות במערכת (לקוחות, תורים, חשבוניות, לידים) קיימות הפעולות הבאות, גם בממשק הווב וגם ב-CLI:

| פעולה | תיאור |
|---|---|
| מחיקה | מסמנת רשומה פעילה כמחוקה |
| שחזור | מסמנת רשומה מחוקה בחזרה כפעילה |
| הצגת פעילים | רשימת כל הרשומות שאינן מחוקות (ברירת המחדל) |
| הצגת מחוקים | רשימת כל הרשומות המחוקות בלבד |
| הצגת הכל | רשימת כל הרשומות, פעילות ומחוקות יחד |

## נתוני דוגמה אוטומטיים

בהרצה הראשונה, אם מסד הנתונים ריק לחלוטין (אין אף לקוח), הפונקציה `seed_if_empty()` (בקובץ `seed_data.py`) ממלאת אותו אוטומטית:

- 12 לקוחות עם שמות, טלפונים, אימיילים וכתובות
- 14 תורים בסוגי שירות שונים (ייעוץ פנסיוני, תכנון פיננסי, ייעוץ השקעות ועוד) בסטטוסים שונים
- 10 חשבוניות מס בסכומים ובתאריכים שונים
- 7 לידים ממקורות שונים (אתר, פייסבוק, המלצה וכו') בסטטוסים שונים
- כמה רשומות מסומנות כמחוקות מראש, כדי שגם תצוגות "מחוקים" ו-"שחזור" יהיו ניתנות להדגמה מיד

אם כבר קיימים נתונים במערכת, הפונקציה לא עושה דבר - הנתונים הקיימים לעולם לא נמחקים או משוכתבים.

## ממשק הווב

ממשק הווב נבנה עם **Flask** בצד השרת ו-**Bootstrap 5 (RTL) + Bootstrap Icons** בצד הלקוח (נטענים מ-CDN). תכונות עיקריות:

- **דף בית** עם לוח מחוונים - ספירת רשומות פעילות בכל ישות, קישורים מהירים להוספה ולצפייה ברשומות מחוקות
- **דף פרטי לקוח** - מציג את כל פרטי הלקוח, החשבוניות הפעילות שלו והיסטוריית התורים שלו במקום אחד, עם טופס הוספת חשבונית ישירות מהדף
- **חיפוש חי (Live Search)** בכל טבלה - סינון שורות בזמן אמת בצד הלקוח, ללא רענון דף
- **תגיות סטטוס צבעוניות** (למשל: ממתין = צהוב, בוצע = ירוק, בוטל = אדום)
- **תפריטי סטטוס עם שליחה אוטומטית** - שינוי סטטוס תור/ליד מתעדכן מיד ללא צורך בלחיצת כפתור נוספת
- **פורמט מטבע** (₪) וסיכום סכומים בדף החשבוניות
- **הודעות Flash** להצלחה/שגיאה על כל פעולה (הוספה, מחיקה, שחזור)
- פתיחה אוטומטית של הדפדפן בעת ההרצה (`webbrowser.open`, עם הגנה מפני פתיחה כפולה במצב Debug)

## פריסה לאינטרנט - אזהרות אבטחה

הפרויקט מוגדר להאזין על `0.0.0.0` כדי לאפשר גישה ממכשירים אחרים ברשת המקומית, אך **אינו מוכן כפי שהוא לחשיפה אמיתית לאינטרנט הפתוח**:

1. `app.run()` מריץ את שרת הפיתוח המובנה של Flask/Werkzeug - לא מיועד לסביבת production. יש להשתמש בשרת WSGI אמיתי (כגון `waitress` ב-Windows או `gunicorn` ב-Linux) מאחורי Reverse Proxy עם HTTPS.
2. `SECRET_KEY` דיפולטיבי לפיתוח בלבד - יש להגדיר משתנה סביבה `SECRET_KEY` עם ערך אקראי וסודי לפני כל פריסה.
3. **אין הרשאות/אימות משתמשים (Authentication)** באף Route - כל מי שמגיע לכתובת יכול להוסיף/למחוק/לצפות בנתוני לקוחות. נדרשת שכבת התחברות לפני חשיפה מעבר לרשת מקומית סגורה.

## פתרון בעיות נפוצות

| בעיה | פתרון |
|---|---|
| טקסט בעברית מוצג הפוך במסוף Windows | הריצו `chcp 65001` לפני `python main.py` |

| ה-`ModuleNotFoundError: No module named 'flask'` | הריצו `pip install -r requirements.txt` |
