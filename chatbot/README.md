# צ'אטבוט אימות ותורים — פרויקט סוף

שכבת שיחה בשפה טבעית מעל ה-API הקיים של פרויקט האמצע (לקוחות ותורים).
משתמש כותב משפט חופשי, הבוט מזהה אותו, מבקש תעודת זהות לאימות,
ואחרי אימות מוצלח מציג את התור האמיתי — כולל תיקון אם המשתמש טעה בתאריך.

**Branch:** `Final_Project_Financial_Advirosy`
**אתר חי:** https://oriai.pythonanywhere.com

## דוגמת שיחה

משתמש: קוראים לי רותם ויש לי תור בתאריך 18.01.2027
בוט: מצאתי 2 לקוחות עם השם הזה. מה השם המלא שלך?
משתמש: רותם מירון
בוט: מצאתי אותך, רותם מירון. מה תעודת הזהות שלך? (לצורך אימות בלבד)
משתמש: 123456789
בוט: מצאתי אותך! שים לב: התור שלך הוא ב-19.01.2027 בשעה 19:00
(ייעוץ פנסיוני), ולא ב-18.01.2027 כפי שציינת.

## קבצים

| קובץ | תפקיד |
|---|---|
| `web.py` | ממשק הצ'אט, ניהול session |
| `bot.py` | מכונת המצבים - הלוגיקה המרכזית |
| `nlu.py` | חילוץ שם ותאריך מטקסט חופשי דרך Gemini, עם נפילה לחילוץ בקוד |
| `api_client.py` | מתווך בין הבוט ל-API - HTTP או קריאה ישירה (`USE_LOCAL_API=1`) |
| `api.py` | JSON endpoints: חיפוש, אימות, תורים |
| `setup_final_data.py` | הכנת דאטה: עמודת ת"ז + לקוחות בדיקה |
| `test_api.py` / `test_client.py` / `test_nlu.py` | בדיקות ידניות לכל שכבה |

## אבטחה

- לפני אימות ת"ז מוצלח: אפס פרטים אישיים נחשפים - לא תאריך, לא שעה, לא אישור קיום תור
- השוואת תעודת הזהות מתבצעת בקוד (`api.py`), לעולם לא ב-Gemini
- תעודת זהות נשלחת רק ב-POST, לא נכנסת לכתובת URL
- 3 ניסיוני אימות, ואז חסימה
- "לקוח לא קיים" ו"ת"ז שגויה" מחזירים את אותה תשובה - אין הבדלה שמסגירה מידע

## תרחישי הבדיקה

הורצו בפועל, מקומית ובשרת:

1. שם ייחודי + תאריך שגוי → תיקון עם התאריך והשעה האמיתיים
2. שם לא ייחודי → הבהרה, לא ניחוש
3. תעודת זהות שגויה, 3 פעמים → חסימה מנומסת
4. לקוח קיים בלי תורים פתוחים
5. שם שלא קיים במערכת

להוראות פריסה מפורטות - ראו `DEPLOY.md` בשורש הפרויקט.
